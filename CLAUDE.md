# coopTracker — правила для Claude

Перед работой прочитай [DESIGN.md](DESIGN.md): там все решения и открытые вопросы. Не принимай заново то, что уже решено; если решение меняется — обнови DESIGN.md.

- Работаем подшагами из раздела «Порядок работы» в DESIGN.md. После каждого подшага — остановка и короткий отчёт пользователю.
- Новые зависимости — только после обсуждения с пользователем: что даёт, чем платим, какие альтернативы.
- `packages/graph-core` — чистый TypeScript без зависимостей в рантайме и без I/O. Сеть, БД, DOM, текущее время и случайность передаются параметрами. Функции не мутируют входные данные, а неизменённые ноды, задачи и стрелки возвращают теми же объектами — от этого зависит скорость интерфейса.
- У каждого правила графа (инвариант, вычисление состояния, слияние) есть тест. До коммита `npm run check` (типы, линтер, Prettier, все тесты) должен быть зелёным. CI на GitHub проверяет то же самое плюс `npm audit`.
- Ошибки возвращаются кодами, а не текстом: тексты живут в переводах интерфейса (русский и английский).
- Коммиты — только после «ок» пользователя. Без строки `Co-Authored-By: Claude` и без любого упоминания Claude как соавтора.
- Никакой игровой терминологии в продукте: редакторы квестов — только референс визуального стиля.

## Команды

- `npm run check` — всё, что нужно перед коммитом
- `npm test` — все тесты: сначала обычные (`npm run test:unit`), потом замеры скорости (`npm run test:perf`)
- `npm run test:watch` — обычные тесты в режиме наблюдения
- `npm run typecheck` — проверка типов во всех пакетах
- `npm run lint` — ESLint с проверками по типам
- `npm run format` — форматирование Prettier (`npm run format:check` — только проверка)
